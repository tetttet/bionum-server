Как сохраняется date-only дата рождения

1. Клиент отправляет дату рождения в JSON body в поле date_of_birth.
   Единственный основной формат API: YYYY-MM-DD, например "2007-01-13".
   Время, timezone и ISO timestamp для этого поля не допускаются.

2. Создание пользователя доступно через два маршрута:
   - POST /api/auth/register
   - POST /api/users

   Редактирование доступно через:
   - PATCH /api/auth/update
   - PUT /api/users/:id

3. Во всех контроллерах date_of_birth проверяется normalizeDateOnly():
   - controllers/auth.controller.js: register()
   - controllers/auth.controller.js: update()
   - controllers/user.controller.js: registerUser()
   - controllers/user.controller.js: updateUser()

4. date_of_birth не входит в список обязательных полей.
   Обязательные поля сейчас: first_name, last_name, email, password.
   Отсутствующее, пустое или null значение сохраняется как NULL.

5. utils/dateOnly.js строго проверяет:
   - формат YYYY-MM-DD;
   - существование месяца и дня;
   - количество дней в месяце;
   - високосный год;
   - отсутствие времени, timezone и лишнего текста.

   Невалидное значение возвращает HTTP 400. JavaScript Date не используется.

6. models/user.model.js передает проверенную строку в PostgreSQL:
   INSERT INTO users (first_name, middle_name, last_name, date_of_birth, email, password)
   VALUES ($1, $2, $3, $4::date, $5, $6)

7. Таблица users создается с колонкой:
   date_of_birth DATE

   Это тип PostgreSQL DATE: сохраняется только календарная дата без времени.

8. Все SELECT/RETURNING используют:
   TO_CHAR(date_of_birth, 'YYYY-MM-DD') AS date_of_birth

   Дополнительно pg type parser для OID 1082 возвращает SQL DATE строкой.
   Поэтому API всегда получает и возвращает YYYY-MM-DD, а не Date/ISO timestamp.

Коротко:
выбор 13.01.2007 -> payload "2007-01-13" -> PostgreSQL DATE
-> API "2007-01-13" -> отображение 13.01.2007.
